# Company

## What it owns

The single `CompanyProfile` row: the operating company's name, website, support and information
addresses, public logo URL, and short description, read by the admin console's Company Profile page.
It does not own contact-form delivery (that is `Contact`) or anything per-user.

## Rules a change must not break

- The profile is a singleton keyed by `CompanyProfile.SingletonId`. Never insert a second row and
  never make the id caller-supplied.
- `GET /api/company` is anonymous and returns 404 until an administrator saves the profile. The web
  admin renders empty fields on 404 rather than inventing placeholder values, so do not start
  returning a synthetic default from here.
- `PUT /api/company` is a full replace and administrator-only. The service, not the controller,
  makes the administrator check.

## Decisions, and what was not built

- One DTO. There is no `AdminCompanyProfileDto`: every field is published company information, so
  an admin split would add nothing but a boundary that does not exist.
- No history, no draft state, no per-locale variants. A six-field profile did not earn them.
- The values live in Postgres, not configuration. The API and admin console read changes immediately;
  the static Marketing site picks them up on its next build or container restart.

## Traps and wiring

- The model is discovered because the API references this project. Stop referencing it from the host
  and the table disappears from generated migrations.
- `Contracts/OpenApi/company.json` is generated by `npm run api:document`. It is listed in
  `Scripts/openapi-manifest.mjs` and in `Apps/Api/OpenApi/ServiceOpenApiDocuments.cs`; both must
  name the document, or the web client's generated types lose the endpoint.
